## Priority Issues

### P1 — Ship within next sprint

**P1-A: Missing `prefers-reduced-motion` in HowItWorks, DoctorCard, CTASection**
- Hero.tsx imports `useReducedMotion` and conditionally applies motion props. The other three components use `motion.div` with `useInView` but never check `useReducedMotion()`. WCAG AA non-compliance. PRODUCT.md explicitly states "Every animation requires a `prefers-reduced-motion` fallback."
- Fix: add `const prefersReduced = useReducedMotion()` in each component; wrap all `motion.*` animate props behind the same conditional pattern Hero uses.
- Files: `components/HowItWorks.tsx`, `components/DoctorCard.tsx`, `components/CTASection.tsx`

**P1-B: No `:focus-visible` rings on interactive elements**
- `WebkitTapHighlightColor: transparent` is set on Hero program rows (line 221) and MagneticButton (line 45) without adding a `:focus-visible` substitute. Keyboard navigation is broken. WCAG AA success criterion 2.4.7.
- Fix: add `outline: '2px solid #4890f7', outlineOffset: '2px'` via CSS class or inline on the `:focus-visible` pseudo. Can be added globally in `globals.css`.

---

### P2 — Design quality

**P2-A: Duplicate "Not sure?" link in Hero**
- Two identical CTA links in the same viewport: one in the CTA button row (line 173: "Not sure? Take the Health Assessment →") and one below the program rows (line 246: "Not sure which program? Take the Health Assessment →"). Redundancy signals indecision to the exact user Apex is trying not to alienate.
- Fix: Remove the one at line 172–174 (inside the CTA div). The placement below the program rows (line 239–247) is better — it's contextually adjacent to the program choice, which is when the question becomes relevant.

**P2-B: Hero `MagneticButton` has no hover interaction**
- CTASection's primary CTA has `onMouseEnter`/`onMouseLeave` with translateY and shadow shift. Hero's `MagneticButton` is a static styled anchor with no hover feedback. Inconsistency. The hero CTA should be at least as interactive as the closing CTA.
- Fix: Add `transition: 'all 0.18s ease'` and onMouseEnter/Leave with `transform: 'translateY(-2px)'` matching CTASection.

**P2-C: Repeated eyebrow label pattern on every section**
- Every section uses the `label` class: "The Process", "Our Medical Team", "Take the first step", etc. brand.md explicitly bans "Repeated tiny uppercase tracked labels above every section heading" as AI scaffolding anti-pattern. These are tolerable as a brand system if intentional, but currently they read as structural scaffolding rather than named brand grammar.
- Fix: Remove eyebrow label from 2–3 sections where the H2 stands alone (DoctorCard "Doctors who specialise in this." is strong enough; HowItWorks "From intake to protocol." is strong enough). Keep eyebrow only where it adds information Hero and CTASection don't.

**P2-D: CTASection program pill arrows imply individual destinations**
- All 7 canonical program pills (e.g. "Sexual Health →") link to the same `/signup` URL. The `→` arrow implies directional specificity — a user clicking "Sexual Health →" expects to land on a Sexual Health intake screen, not a generic signup page.
- Fix: Either (a) remove the `→` from pill labels so they read as tags not links, or (b) add a brief clarification note below the pills: "Select your program after sign up." Option (b) is more transparent and aligns with H1.
